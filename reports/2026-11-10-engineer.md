## Ticket 1-5 (one event, five copies): QuoteClose failed on 2026-11-10

### What actually happened
The context note says QuoteClose "ran Tue 11-10 **15:30**", not its frozen 12:56 PT time. Evidence:
- `state/logs/` has `2026-11-10-quote_clerk-open.jsonl` (06:31) but **no** `2026-11-10-quote_clerk-close.jsonl`.
- `state/usage.csv` has one `2026-11-10,quote_clerk,...,ok` row (the open) and **no** close row.
- `quote_task.log` has the 11-10 open line, no 11-10 close line.

`quotes.py capture("close")` writes the stream jsonl (`quotes.py:175`), the usage row (`quotes.py:207`) and
the log line (`quotes.py:308`) only after it gets past launching Claude. None of the three exists, so the run
crashed *before* launching the clerk, i.e. in `needs()` / config load / the subprocess launch (`quotes.py:142-173`).

Why it ran at 15:30: the machine was asleep/off through the 12:56 frozen window (today's dispatch itself is
running late too, ~15:30, well inside its 20:00 retry window). Task Scheduler fired the missed QuoteClose on wake,
~2.5h after the US close, so any quote it fetched would be stale/after-hours anyway. scan_ops could not have
re-run it validly — its window (`retry_until` 12:59) had long closed, and scan_ops wasn't ticking while asleep.

**Cause:** environmental (machine asleep at the 12:56 frozen window), not team code. `quotes.py`, the Windows
task and the V4 ledger are all outside my editable list, so I did not change them. The day is a genuine one-day
gap in the ON1/EPRE real-price capture, already reported to #agent-ops by the Scan Operator.

### The machinery bug I did fix: 1 failure → 5 tickets
`scan_ops.py` recorded the SAME failure five times. In the give-up branch, `once()` gates the Discord alert, but
the `st["issues"].append(...)` ran on **every** 10-min tick after the retry window closed (`scan_ops.py:123`).
Five ticks after 15:30 → five identical `issues` entries → `engineer.py collect()` (`engineer.py:183-185`) turns
each into its own ticket. Worse, `engineer.py prepare()` increments the per-key attempt counter once per copy
(`engineer.py:235-236`), so one failure burns the whole 2-attempt budget in a single run and the next run would
post "tried too many times, needs you" for something seen once.

**Fix:** dedupe the append — one issue per (date, job, problem), matching the single alert.
`tools/scan_ops.py:123` now appends only if that exact issue isn't already recorded.

**Proven:** `tests/test_eng_scan_ops_dedup.py` drives five post-window ticks on a failed task and asserts exactly
one issue is recorded (without the fix it would be five). Guard OK, full suite 78 passed.

## Proposals for the user
1. **Keep the machine awake at 12:56 PT on weekdays** (or let the user's session add "Wake the computer to run
   this task" to `StockAnalysis_Team_QuoteOpen`/`QuoteClose`, and/or "run as soon as possible after a missed start"
   OFF for these two frozen tasks). A missed frozen-window capture is a lost day of real-price data and there is
   nothing a role can do to recover it. Tasks/wake settings are user-only.
2. **Optional robustness in `quotes.py` (not my editable file):** have `capture()` return a clean
   "stale window, skipped" instead of launching the clerk when it runs well past its scheduled minute (so a late
   catch-up run exits 0 rather than erroring and raising a failure ticket). Does not change what any test measures.
   Would need the user's session since `quotes.py` is off the Engineer's list.
