## Ticket: Scan StockAnalysis_Team_ScanOps exited with an error on 2026-11-10 and could not be re-run validly

**Cause.** Not a new failure. This is the same 2026-11-10 self-flag I diagnosed and fixed on 2026-11-11
(scan_ops.py:94-101, the `if name == OWN_TASK: continue` self-skip, proven by test_eng_scan_ops_self_flag.py).
That fix is confirmed working: scan_ops.json has no new `gave_up:ScanOps` on 2026-11-11 or 2026-11-12, and scan_ops
has ticked cleanly every 10 min today. The machine never actually crashed on 2026-11-10 — a post-sleep snapshot
caught a stale terminated LastResult.

The reason the ticket came back: the self-flag fix stopped scan_ops from writing *new* ScanOps issues, but the one
it wrote on 2026-11-10 (before the fix) still sat in `state/scan_ops.json` `issues`. scan_ops only prunes that list
by age (one week), so the stale record would live until 2026-11-17. `engineer.py collect()` (engineer.py:183-185)
re-reads every issue in that window each dispatch and files it as an urgent ticket — so it replayed a phantom
"ScanOps exited with an error" every run, and was about to hit the 2-attempt cap and falsely tell you the Engineer
"tried twice and couldn't fix" an issue that is already fixed.

**What I changed.** Completed the self-flag fix at its source. scan_ops.run() now drops any `issues` entry whose
job is `OWN_TASK` when it prunes (scan_ops.py:150-155). Since scan_ops no longer judges its own run, a ScanOps row
in that list can only be pre-fix false-positive residue, so purging it is correcting a wrong record, not silencing a
real one. Real ScanOps failures are caught independently by `ops_monitor.check_tasks` (ops_monitor.py:110), which
inspects every scheduled task from the Task Scheduler snapshot and does not read this list — so no coverage is lost.

**Proven by.** New case `test_prune_drops_stale_own_task_issue` in tests/test_eng_scan_ops_self_flag.py: seeds a
stale 2026-11-10 ScanOps issue plus a genuine same-day failure of another job, runs scan_ops.run(), and asserts the
ScanOps record is gone while the real failure is kept. Guard OK; 85 tests pass. (Edited, pending the guard — the
guard's verdict is posted right after this.)
