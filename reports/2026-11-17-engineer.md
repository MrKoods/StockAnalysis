# Engineer report 2026-11-17 (Tue)

4 failure tickets, all ONE root cause: the **claude.ai Webull MCP server was not authenticated**
in all four Quote windows (open + close) on 2026-11-16 and 2026-11-17. This is the same failure
mode diagnosed on 2026-11-16 (reports/2026-11-16-engineer.md); it recurred because the Webull MCP
re-auth was not done, or did not persist across the scheduled task launches.

## Tickets

1. Scan StockAnalysis_Team_QuoteOpen exited with an error 2026-11-16 (scan_ops)
2. Scan StockAnalysis_Team_QuoteOpen exited with an error 2026-11-17 (scan_ops)
3. Ops Monitor: Team_QuoteClose ran 11-17 12:56 but FAILED (result 1)
4. Ops Monitor: Team_QuoteOpen ran 11-17 06:31 but FAILED (result 1)

### Cause (file:line + evidence)
- The Quote Clerk (Haiku) ran on time and Claude itself was logged in and working: both 11-17
  logs show it thinking and issuing ToolSearch calls. Example final turn,
  `state/logs/2026-11-17-quote_clerk-open.jsonl:461-462`: the clerk concludes *"Webull
  authentication is required. Please run `/mcp` ... select 'claude.ai Webull' to authenticate.
  Once you complete the OAuth flow, the `get_stock_snapshot` tool will become available"* and the
  session result is `subtype:"success", is_error:false, num_turns:7` — i.e. Claude ran fine; only
  the Webull MCP was unavailable.
- Both 11-17 sessions (`...-open.jsonl` init line 1, `...-close.jsonl` init line 1) show
  `mcp_servers: [... {"name":"claude.ai Webull","status":"pending"} ...]`. Every
  `ToolSearch select:mcp__claude_ai_Webull__get_stock_snapshot` returned "No matching deferred
  tools found"; broad "webull" searches returned only `__authenticate` /
  `__complete_authentication`. So `get_stock_snapshot` (the clerk's only allowed tool,
  `tools/quotes.py:40`) was never exposed.
- With no quote rows parseable, `quotes.py` captures nothing and exits 1 (its NOTHING-captured
  path, `quotes.py:221`). That non-zero exit is what the Quote Windows tasks report as result 1,
  which `ops_monitor.check_tasks` and `scan_ops` correctly turn into tickets.
- `apiKeySource:"none"` in the init line is NORMAL for these headless subscription runs and is NOT
  the logout signal (settled 2026-11-16). The real signal is the Webull MCP server status + which
  Webull tools are exposed. This is therefore NOT the 2026-11-13 full-Claude logout
  (`quotes.py`'s `LOGGED_OUT_RX`/`LOGIN_HELP` guard did not and should not fire here).

### What I changed
Nothing. Everything that could fix this — `tools/quotes.py`, the `StockAnalysis_Team_QuoteOpen` /
`QuoteClose` Windows tasks, and the MCP OAuth login — is outside the Engineer's editable list. The
scan_ops and ops_monitor checks are CORRECT: the tasks genuinely failed, so there is no wrong check
to fix and nothing to quiet. Closing a correct failure ticket with a code change would be exactly
the "make a warning quieter" move the charter forbids.

### Impact
Real-price (Webull bid/ask) capture is now missing for 2 trading days (4 windows: 11-16 open+close,
11-17 open+close). That feeds ON1's real-price verdict (needs 15 quote days, ~2026-11-23) and EPRE's
real-price status. Each lost window pushes those dates later and leaves a gap in the ledgers. The
loss is unrecoverable by design (quotes.py refuses late captures, `too_late`, `quotes.py:142`).
